# Лабораторная № 1 — StudyToken

Цель работы — написать контракт, развернуть его в локальной EVM, отправить транзакцию перевода и сверить состояние с её журналом. [Исходник StudyToken.sol](contracts/StudyToken.sol) самодостаточен и использует Solidity 0.8.24.

При развёртывании владелец получает **1000 STC**. Только владелец может вызвать `mint`. После выпуска в обращении может находиться не более **100 000 STC**. `burn` сжигает токены вызвавшего аккаунта и освобождает часть лимита текущей эмиссии.

Суммы в контракте — целые числа в минимальных единицах. При `decimals = 18` один STC равен `1000000000000000000` минимальных единиц. Для 10 STC введите **`10000000000000000000`**. `transfer` переводит собственные токены, `approve` задаёт лимит списания другому адресу, `transferFrom` расходует этот лимит. `Transfer` фиксирует перевод, выпуск и сжигание, `Approval` показывает установку или изменение разрешения.

`approve` даёт указанному адресу право списать токены. Сверяйте адрес и размер лимита. При изменении уже выданного лимита spender может успеть использовать старый лимит перед подтверждением нового. Для замены сначала подтвердите `approve(spender, 0)`, проверьте баланс и затем задайте новое значение. Реализован основной интерфейс ERC-20 для учебного сценария. Формальный аудит в работу не входит.

## Демонстрация в Remix

1. Откройте Remix IDE. При переадресации на `app.remix.live` продолжите в открывшемся редакторе. В **File Explorer** создайте `StudyToken.sol` и вставьте исходник целиком. [Remix IDE](https://remix.ethereum.org/)
2. В **Solidity Compiler** выберите **0.8.24**, указанную в `pragma`. Нажмите **Compile StudyToken.sol**.
3. В **Deploy & Run Transactions** выберите локальный **Remix VM**. Например, используйте вариант Cancun или Prague, если он доступен. Выберите первый тестовый аккаунт, убедитесь, что выбран контракт **StudyToken**, и нажмите **Deploy** с `Value = 0`. Раскройте инстанс в **Deployed Contracts**.
4. Скопируйте адрес первого аккаунта и адрес второго аккаунта из списка **Account**. Переключитесь обратно на первый аккаунт. Вызовите `balanceOf` для обоих адресов. Ожидаются `1000000000000000000000` и `0`.
5. В `transfer` введите второй адрес в поле `to` и `10000000000000000000` в `value`. Отправьте транзакцию с первого аккаунта. Повторите `balanceOf`. Ожидаемые значения после подтверждения — `990000000000000000000` и `10000000000000000000`.
6. Найдите запись `StudyToken.transfer` в нижнем терминале и раскройте её. Если история вынесена в отдельную вкладку, откройте **Transaction History** в панели Deploy. Проверьте успешный `status`, полный `transaction hash`, `from` с первым аккаунтом и `to` с адресом **контракта**. Адрес получателя и сумму покажет декодированный ввод. В `logs` найдите `Transfer` с первым адресом, вторым адресом и суммой. Сверьте событие с выводом `balanceOf`.
7. Если у записи доступна кнопка **Debug**, откройте её и пройдите к изменению балансов в `_transfer`. [Документация панели Deploy & Run](https://remix-ide.readthedocs.io/en/latest/run.html)

### Снимки для отчёта

1. Компиляция Solidity 0.8.24 или успешный деплой в Remix VM с видимым именем контракта и его адресом.
2. Раскрытая транзакция `transfer` с хешем, статусом, декодированным вводом и событием `Transfer`.
3. Результаты `balanceOf` после перевода для двух адресов. Их можно показать в двух раскрытых записях терминала на одном снимке.

## Автоматическая проверка

Из корня репозитория в PowerShell выполните команды ниже. На macOS и Linux используйте `npm` вместо `npm.cmd`.

```powershell
npm.cmd --prefix coursework/blockchain ci
npm.cmd --prefix coursework/blockchain run compile
npm.cmd --prefix coursework/blockchain run test -- test/StudyToken.test.js
```

Для повторяемой демонстрации откройте отдельный терминал с `npm.cmd --prefix coursework/blockchain run node`. Затем запустите `npm.cmd --prefix coursework/blockchain run demo:study` из корня. Скрипт создаёт новый StudyToken, переводит 10 STC и показывает receipts, события и балансы. Для сдачи лабораторной используются отдельные снимки Remix VM.
